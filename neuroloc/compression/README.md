# neuroloc compression research corpus

status: current (as of 2026-05-14).

## purpose

this folder is the dedicated compression research product for neuroloc. it records what has been tried, what the field already covers, what must be used as a baseline, what the hard information limits are, and the next buildable candidate path.

the current product is not a promoted 600x proof. it is the research and engineering front door for the next attempt. the project has a local full small nm candidate on exact-state 3d tasks, a bounded exact qa adapter/update benchmark, a narrow lossless source-code block codec product, a broader frozen-manifest source-code corpus codec product, a narrow source-authored relation-index product, an external relation adapter product, and the broader public multi-surface model-state knowledge pack. high-density exact knowledge compression remains gated.

## simple thesis

the next credible path is simple:

- learn a shared predictor over non-generated data.
- encode held-out exact values with an entropy coder under that predictor.
- store no per-fact value or residual rows.
- charge the model, codebooks, arithmetic streams, keys, manifests, dictionaries, training side information, and every fallback bit.
- require the random-label twin to collapse.
- beat the charged corpus-codec baseline, product-key memory, sparse read, and verbatim storage at matched exact success.

if the result still needs one residual stream per fact, it is another table. if it retrieves independent random labels exactly under the same budget, it is another table. if it only beats no-memory, it is not enough.

## current product and constraint

the current narrow compression product is `local_100k_source_subtoken_structure_block_codec`: a source-code transform that keeps the train-learned indentation split, delta-codes the indentation-count plane, and adds a fully charged target identifier dictionary for longest-match body subtoken substitution before the fair same-block standard codec sweep. hard validation reconstructs `99761` held-out source bytes exactly from charged compressed count-delta, body-subtoken, and dictionary streams, carries those streams and codec selectors through a reloadable torch module state dict, reports path/hash train-test overlap counts at `0.0`, charges an `896` bit subtoken-structure header, and improves strict charged bits over the best fair same-block standard codec by `0.048648916163515785`. charged payload bits drop from the prior source-token product's `123088` to `120952`; random-label bytes do not receive a compression gain (`-0.0013331194996291321`), disabled controls collapse, no raw/count/body/restored block is retained as state, and `source_block_codec_product_authorized` is `1.0`.

the current broader corpus product is `local_100k_source_subtoken_global_stream_corpus_codec`: a frozen-manifest five-block source-code benchmark that keeps source-structure count coding and one charged corpus-shared subtoken dictionary, but compresses one global count stream, one global body stream, and one charged framing stream across the whole corpus. hard validation reconstructs all blocks exactly, checks the frozen block hashes, requires random-label payload incompressibility, reloads the charged payload from torch module `state_dict`, charges a conservative `2048` bit global header, and reduces aggregate selected payload bits from the previous shared-dictionary corpus product's `803400` to `699144`. aggregate payload improvement over the best same-block standard sweep rises from `0.05454767979363391` to `0.1772375940274339`, and the product also beats a stronger global raw standard baseline at `736504` bits by `37360` bits. this supersedes `local_100k_source_subtoken_shared_dictionary_corpus_codec`, while `local_100k_source_subtoken_structure_corpus_codec` and `local_100k_source_token_structure_corpus_codec` remain superseded or diagnostic baselines.

the current narrow exact-retrieval product is `local_100k_source_subtoken_disjoint_retrieval_codec`: a disjoint frozen-source chunk retrieval surface built from the global-stream codec. hard validation retrieves `14715` aligned 32-byte chunks exactly after torch `state_dict` reload, uses zero train path/hash overlap against the structure-training source set, charges `431536` retrieval bits, beats executable raw content scan at `451128` bits by `19592` bits, beats an undercharged mph diagnostic at `451144` bits by `19608` bits, and keeps random-label/control gates passing. this is source-code exact retrieval, not learned semantic qa and not broad breakthrough authorization.

the current source-authored relation result is `local_100k_source_authored_relation_diagnostic`: a diagnostic, not a product. it answers `337` authored definition/import relation queries exactly after `state_dict` reload and shows read-work gain over an unlimited no-index scan, but a fair unlimited relation-aware scanner solves the same task and an honest mph relation index is cheaper by `132664` bits. this blocks relation-product promotion and confirms that the next relation attempt needs a genuinely harder relation surface or a stronger charged index advantage.

the dense source-authored relation result is `local_100k_source_dense_authored_relation_diagnostic`: also a diagnostic. it expands the authored relation surface to `3741` definition-parent, statement-enclosing, and control-statement-enclosing queries after removing an answer-contained signature query leak documented in [[mistakes/dense_relation_signature_query_leakage]]. hard validation answers exactly and beats honest relation mph/index by `2928400` bits, proving that compressed source can amortize many authored relations better than per-relation indexing. it still loses to paq8px level 2 by `176536` bits and does not beat a fair unlimited relation-aware scanner, so product authorization stays `0.0`.

the current narrow source-authored relation-index product is `local_100k_source_relation_mph_codec`: it stores a charged minimal-perfect-hash-style router, 17-bit fingerprints, compressed value/provenance id streams, and compressed value/provenance dictionaries inside torch module state. hard validation answers `3741` keyed authored relation queries exactly after `state_dict` reload, charges `248784` selected relation bits, recomputes the paq8px level 2 relation line in-run at `252952` payload bits plus `8192` decoder bits, beats that paq8px line by `12360` bits, beats raw-source paq content scan by `165104` bits, beats an undercharged mph relation diagnostic by `2522477` bits, beats an honest mph relation index by `3117296` bits, and reaches `67.90445687825584x` strict multiplier. cross-scored random labels, disabled decode, shuffled fingerprints, and hardened wrong-query variants collapse; a separately rebuilt random-label codec stores exactly but costs `934984` bits, so the density-control path collapses rather than pretending random entropy was impossible to store. this is a narrow keyed relation-index product only. self-contained paq8px baseline-win authorization is `1.0`; static breakthrough, strict 600x, broad knowledge, broad nm, arbitrary chat, and full nm authorization remain `0.0`.

the current external llm-adoptable relation adapter product is `local_100k_external_relation_adapter`: it moves the relation-index path onto pinned public cpython `v3.12.3` source files and packages the charged relation payload inside tiny transformer-style, recurrent/state-style, and state-space-style hosts. hard validation answers `6247` public-corpus relation facts exactly, charges `413600` selected relation bits plus a `4096` bit model-package header, reaches `35.65344680851064x` strict multiplier and `35.303822875967214x` model-package strict multiplier, recomputes paq8px v214 level 2 on the external source scan at `606072` accounted bits, beats that public source-scan line by `192472` bits, beats honest mph indexing by `3098120` bits, and keeps random-label, disabled, parser-disabled, shuffled-fingerprint, wrong-query, raw-source-retention, and full-question-table controls collapsed. this is now the source-only predecessor to the broader model-state knowledge pack.

the current broader paper-facing product is `local_100k_model_state_knowledge_pack`: it compiles pinned cpython `v3.12.3` source, documentation, and config authored relation facts into charged torch module state and packages the payload through tiny transformer-style, recurrent/state-style, and state-space-style hosts. hard validation answers `9754` relation facts exactly, charges `679400` selected relation bits plus an `8192` bit model-package header, reaches `37.6093164556962x` strict multiplier and `37.1612374780393x` model-package strict multiplier, recomputes paq8px v214 level 2 source-scan pressure at `1385264` accounted bits, beats that strongest checked line by `705864` bits, beats zstd level 19 source scan by `1515616` bits, beats honest mph indexing by `5194024` bits, beats product-key-style storage, rag/knn storage, lora-style exact payload lower bound, and model-edit exact payload lower bound, and passes adapter export, recompress update, rollback, transformer, recurrent, and state-space host probes. this is the first paper-facing bounded knowledge-pack product, not ordinary base-weight implicit storage, arbitrary chat, broad open-domain knowledge compression, full nm completion, or strict 600x proof.

the current public trained-dictionary audit is `local_100k_zstd_trained_dictionary_baseline_audit`: charged zstd dictionaries trained only on target-excluded local source files lose to the current source-subtoken block payload by `30424` bits and to the new global-stream frozen-corpus payload by `283696` bits. the undercharged payload-only dictionary diagnostic also loses by `26248` bits on the block and `250848` bits on the corpus. this strengthens the source-code codec products, but it is a baseline audit and does not create a new product claim.

the new public context-mixing pressure line is paq8px v214. the 2026-05-14 scratch audit compressed the hard raw joined source from `802589` bytes to `50712` archive bytes at level 2, or `405696` payload bits. this beats the current global-stream corpus payload at `699144` bits by a large margin, so the source-code byte-compression claim is no longer competitor-beating against the strongest checked public compressor. see [[mistakes/public_context_mixing_baseline_missing]].

## required promotion rule

a future broad compression result is not promoted unless all of the following are true:

- exact held-out retrieval is at least `0.95`.
- strict density beats the charged corpus-codec baseline, the current margin adapter product, executable same-block content scan, and all explicit baselines.
- random-label twin exact retrieval collapses.
- no per-fact value, residual, provenance, or hidden assignment rows are needed.
- one independently addressable entropy-coded value slice per fact is treated as a payload table unless it is reported only as a fully charged codec baseline.
- shuffled key, shuffled value, shuffled provenance, disabled decoder, disabled write, disabled read, disabled dictionary, and wrong-code controls collapse.
- all storage, parser, decoder, codebook, manifest, training-side, exception, and key bits are charged.
- the result states what is still not proved.
