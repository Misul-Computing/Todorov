# Modular CPU pilot closure and quadratic ledger defects

status: historical context only. frozen as of 2026-07-22. do not edit.

The first canonical local CPU attempt completed its resource pilot but could
not package the normal stop. `_closure_expected_paths` collected detail hashes
from preflight only. `run/pilot.json` referenced two additional content-
addressed detail files, so exact closure rejected files generated by the same
pilot. The error path then removed the provisional pilot record. The run root
preserves the unterminalized evidence and must not be repaired in place.

The bug class is incomplete transitive artifact closure. Every retained
artifact that may reference content-addressed detail files must participate in
closure derivation for every lifecycle state that retains it. The repair adds
`run/pilot.json` as a detail-reference source for pilot stop, claim abort, and
clean completion. The regression constructs separate preflight and pilot
detail hashes, terminalizes the exact set, verifies the checksum, and proves
that the pilot record survives.

The same investigation exposed quadratic claim-ledger work. Every append read
the entire committed prefix before writing one line, and the claim parent then
parsed and revalidated the complete per-seed ledger after each attempt event.
At `20,736` updates this is unnecessary growing-prefix work. The repair keeps
an incremental digest, exact started/completed finite-state machine, duplicate
identity set, and attempted/completed accounting. A successful append performs
bounded size and line readback; only a failed append rereads the committed
prefix for truncate, fsync, and digest-verified rollback. Complete canonical
parsing and sequence validation still run at close and terminal packaging.

The read-work regression originally measured `1,006,342` requested read bytes
at 256 fixture rows versus `246,022` at 128 rows, a `4.09x` increase when the
event count doubled. It now requires at most `2.2x`. Existing short-write,
write, fsync, readback, handled-signal, truncate, rollback-fsync, and rollback-
read fault tests remain mandatory.

Neither defect justifies relaxing scientific work. No seed, update, token,
task, intervention, control, gate, or evaluation may be removed for speed. The
hard launch rule is now an end-to-end pilot projection at or below twenty
minutes, with ten minutes as the target.
