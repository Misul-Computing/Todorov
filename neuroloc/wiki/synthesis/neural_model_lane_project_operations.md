# neural model lane: project infrastructure, curriculum, and paper operations

status: current (as of 2026-04-26).

## thesis

the project needs one canonical plan, gated side-paper handling, private-until-proved policy, prosecutor-clean documentation, and explicit archive discipline. `PROJECT_PLAN.md` is the single session-start plan. subordinate state files summarize or specialize it; they do not compete with it.

the curriculum is preserved as a support lane. old architecture execution is historical evidence, not the active identity.

## ranked unknowns

1. which old architecture pages should later move under `neuroloc/wiki/archive/`.
2. how to keep side-paper candidates from becoming undocumented scope creep.
3. what source hierarchy prevents future sessions from re-reading every plan file.
4. what prosecutor checklist is needed for paper-grade theory pages.
5. when a mechanism deserves a side paper rather than a paragraph inside the flagship paper.

## proof gates

- every side-paper candidate must define mathematical operation, prior-art boundary, preserved or improved operation, source or proof basis, symbolic or oracle bound, trainable test, controls, telemetry, kill condition, and paper claim if proved.
- every wiki/state update that changes canonical project state updates `PROJECT_PLAN.md` first, then subordinate files as needed.
- prosecutor review cycles to zero findings on synthesis, tests, project-state, and state-file changes.
- archive moves happen only in a focused migration pass after the archive policy is added to the directive.
- paid compute stays blocked until broad research, oracle bounds, tiny mirror, cpu controls, telemetry, prosecutor-clean docs, and one selected hypothesis exist.

## side-paper candidates

- operation-preserving compression stack.
- hard symbolic neural-model test material.
- cellular/local state storage.
- replay and imagination compression.
- trainability failure and control methodology.

## kill conditions

- multiple plan files again become competing sources of truth.
- a side-track lacks proof gates but starts driving implementation.
- old architecture execution language becomes the active identity.
- docs claim novelty or proof before evidence exists.
- paid compute is treated as exploration rather than a gated validation step.
